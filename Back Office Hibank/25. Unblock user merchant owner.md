# 1 Deskripsi Use Case

**Tabel 1: Deskripsi Use Case Unblock User Merchant Owner**

| Elemen Spesifikasi | Deskripsi Detail |
| --- | --- |
| ID Use Case | UC-BOH-025 |
| Nama Use Case | Unblock User Merchant Owner |
| Penjelasan Singkat | Fitur Web Back Office Hibank pada menu App Config -> Users Management (Tab User Merchant) yang memfasilitasi User Bank untuk memfilter akun ber-role `MERCHANT_OWNER` berstatus `Blocked` dan membuka kembali blokir (*unblock*) akun Merchant Owner pada tabel `mst_users` melalui System Management Service (`system_management_service`), sehingga Merchant Owner dapat melakukan login kembali ke Portal Back Office Merchant. |
| Aktor Utama | User Bank (Back Office Hibank Compliance / Risk / Operations Staff) |
| Aktor Pendukung | System Management Service (`system_management_service`), Notification/Email Service |
| Deskripsi Singkat | User Bank melakukan otentikasi login SSO ke Web Back Office Hibank dan mengakses menu **App Config** -> **Users Management**. Sistem menampilkan halaman pengelolaan pengguna dengan beberapa tab. User Bank memilih tab **User Merchant**. Sistem menyajikan toolbar pencarian dan filter data. User Bank memasukkan/memilih kriteria filter berdasarkan **Nama Merchant**, memilih filter Role **`MERCHANT_OWNER`**, dan memfilter Status **`Blocked`**. Sistem menampilkan daftar akun pengguna Merchant Owner berstatus diblokir dari tabel `mst_users`, `mst_merchants`, dan `mst_roles`. User Bank memilih baris akun Merchant Owner yang akan dibuka blokirnya, lalu mengklik tombol aksi **"Edit"**. Sistem menampilkan modal/halaman formulir pengeditan data pengguna merchant. User Bank mengubah pilihan kolom Status Pengguna dari `Blocked` menjadi **`Active`** dan menginputkan Alasan Pembukaan Blokir (*unblocking reason*). User Bank mengklik tombol **"Simpan Data"**. Front-End memvalidasi kelengkapan data dan mengirimkan request pembukaan blokir ke API Gateway. Service `system_management_service` memvalidasi status akun. Setelah validasi sukses, service memperbarui status akun Merchant Owner pada tabel **`mst_users`** menjadi **`login_status = ACTIVE`** (atau me-reset alur *First Time Login* jika disyaratkan) dan mencatat jejak pembukaan blokir ke tabel **`audit_logs`**, serta memicu Notification/Email Service untuk mengirimkan notifikasi aktivasi kembali ke email Merchant Owner. Front-End memperbarui tabel daftar user merchant dan menampilkan notifikasi konfirmasi bahwa akun Merchant Owner telah berhasil di-unblock. |
| Pre-condition | 1. User Bank telah berhasil login SSO ke Web Back Office Hibank dan memiliki hak akses menu *App Config - Users Management*.<br>2. Akun Merchant Owner yang akan dibuka blokirnya terdaftar pada tabel `mst_users` dengan status diblokir (`login_status = BLOCKED`). |
| Post-condition | 1. Kolom `login_status` akun Merchant Owner pada `mst_users` diperbarui secara langsung menjadi `ACTIVE`.<br>2. Akun Merchant Owner kembali dapat melakukan otentikasi login dan mengakses Portal Back Office Merchant.<br>3. Notifikasi pembukaan blokir berhasil dikirimkan ke email terdaftar Merchant Owner.<br>4. Front-End memperbarui tampilan tabel daftar user merchant pada tab User Merchant menu App Config. |
| Trigger | User Bank mengakses menu **App Config** -> **Users Management**, memilih tab **User Merchant**, memfilter **Nama Merchant**, Role **`MERCHANT_OWNER`**, dan Status **`Blocked`**, mengklik tombol **"Edit"**, mengubah status menjadi **`Active`**, mengisi alasan unblock, dan mengklik **"Simpan Data"**. |
| Nama Tabel | mst_users, mst_roles, mst_merchants, audit_logs |
| Integrasi | 1. **Web Back Office Hibank UI:** Antarmuka menu App Config - Users Management (Tab User Merchant), filter toolbar, dan form edit user merchant.<br>2. **System Management Service:** Microservice backend pengelola pembaruan status keaktifan akun merchant di database.<br>3. **Notification/Email Service:** Layanan pengiriman notifikasi pembukaan blokir akun ke email Merchant Owner. |
| Asumsi | 1. Pembukaan blokir akun Merchant Owner mengembalikan akses penuh pengguna ke Portal Back Office Merchant.<br>2. Alasan pembukaan blokir dicatat secara eksplisit pada log perubahan untuk kebutuhan *audit trail*. |
| Keterbatasan | 1. Akun Merchant Owner yang sudah berstatus aktif (`login_status = ACTIVE`) tidak dapat di-unblock ulang.<br>2. Pengisian alasan pembukaan blokir bersifat mandatori dan tidak boleh dikosongkan. |
| Aturan Bisnis/Sistem | 1. **Navigation & Scoping:** Fitur unblock user merchant owner dikelola terpusat pada menu **App Config** -> sub-menu **Users Management** -> tab **User Merchant**.<br>2. **Filter & Search Criteria:** Toolbar filter mendukung pencarian berbasis **Nama Merchant** (`merchant_name`), peran **`MERCHANT_OWNER`**, dan status **`Blocked`** (`login_status = BLOCKED`).<br>3. **Edit Form Status Modification:** Pembukaan blokir dilakukan via form Edit User Merchant dengan mengubah field Status dari `Blocked` menjadi `Active` serta menginput field wajib `Unblocking Reason`.<br>4. **Direct Database Update (`mst_users`):** Sistem memperbarui kolom `login_status = ACTIVE`, `updated_at`, dan `updated_by` pada tabel `mst_users`.<br>5. **Notification Trigger:** System Management Service memicu event pengiriman notifikasi informasi unblock akun ke email Merchant Owner.<br>6. **Audit Trail Logging:** Setiap tindakan pembukaan blokir wajib mencatat ID pelaksana, timestamp, ID merchant, dan alasan pembukaan blokir ke tabel `audit_logs`. |
| Session Idle | 15 Menit |

alt Alasan Kosong [AF-01]
  fe --> user : Tampilkan Pesan "Alasan pembukaan blokir wajib diisi"
else Form Valid
  fe -> gateway : Request Update User Status (Payload: status=ACTIVE, reason)
  gateway -> service : Teruskan Request Update User Status
  
  service -> db : Query login_status owner pada mst_users
  db --> service : Return Data Owner Status

    service -> db : Insert audit_logs (action=UNBLOCK_MERCHANT_OWNER, user_id)
    db --> service : Confirm Update Owner User Status
    
    service -> notif : Trigger Send Unblock Email Notification (owner_email)
    notif --> service : ACK Email Triggered
    
    service --> gateway : Response Sukses (HTTP 200 OK)
