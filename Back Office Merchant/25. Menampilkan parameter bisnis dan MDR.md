# 1 Deskripsi Use Case

**Tabel 1: Deskripsi Use Case Menampilkan Parameter Bisnis dan MDR**

| Elemen Spesifikasi | Deskripsi Detail |
| --- | --- |
| ID Use Case | UC-BOM-025 |
| Nama Use Case | Menampilkan Parameter Bisnis dan MDR |
| Penjelasan Singkat | Fitur Back Office Merchant pada menu My Business yang memfasilitasi Merchant Owner untuk melihat informasi rincian parameter aturan bisnis (seperti Hari Settlement `H+0`/`H+1`, minimum batas pencairan) serta daftar tarif MDR (*Merchant Discount Rate*) yang ditetapkan untuk entitas merchant dari tabel `mst_merchants`, `mst_merchant_business_rules`, `business_type_category_details`, dan `mst_merchant_mdr_details` melalui Merchant Management Service. |
| Aktor Utama | Merchant Owner |
| Aktor Pendukung | Merchant Management Service (`merchant_management_service`) |
| Deskripsi Singkat | Merchant Owner melakukan otentikasi login ke Back Office Merchant dan mengakses menu **My Business**. Pada halaman My Business, Merchant Owner memilih tab **Business Rules**. Sistem menampilkan daftar parameter aturan bisnis yang terikat pada merchant tersebut (seperti Siklus Hari Settlement `H+0`/`H+1`, Minimum Settlement Amount, dan Frekuensi Settlement) dari tabel `mst_merchant_business_rules` dan `mst_merchants`. Selanjutnya, Merchant Owner memilih tab **MDR**. Sistem memuat dan menampilkan rincian kategori jenis usaha merchant (misal: UMI / UKE) beserta daftar kriteria nominal transaksi dan tarif persentase MDR yang berlaku bagi merchant tersebut dari tabel `business_type_category_details` dan `mst_merchant_mdr_details` (termasuk indikasi apabila tarif MDR tersebut menggunakan tarif khusus *override*). Front-End menyajikan data rincian konfigurasi bisnis dan tarif MDR dalam antarmuka yang bersih dan *read-only*. |
| Pre-condition | 1. Merchant Owner telah berhasil login ke Back Office Merchant dan berstatus aktif.<br>2. Entitas merchant terdaftar aktif pada tabel `mst_merchants` beserta konfigurasi aturan bisnis dan tarif MDR. |
| Post-condition | 1. Sistem menyajikan informasi lengkap parameter aturan bisnis (seperti Hari Settlement) pada tab Business Rules.<br>2. Sistem menyajikan rincian skema dan persentase tarif MDR yang berlaku pada tab MDR.<br>3. Tidak ada perubahan data yang dilakukan pada database (proses murni *read-only*). |
| Trigger | Merchant Owner mengklik menu **My Business**, memilih tab **Business Rules** untuk melihat parameter bisnis, lalu memilih tab **MDR** untuk melihat daftar skema tarif MDR merchant. |
| Nama Tabel | mst_merchants, mst_merchant_business_rules, business_type_category_details, mst_merchant_mdr_details, audit_logs |
| Integrasi | 1. **Back Office Merchant UI:** Antarmuka pengelolaan bisnis merchant (halaman My Business), tab navigasi Business Rules, dan tab navigasi MDR.<br>2. **Merchant Management Service (`merchant_management_service`):** Microservice backend penyedia data parameter bisnis, pengambil skema MDR merchant, dan otorisasi. |
| Asumsi | 1. Tampilan informasi parameter bisnis dan MDR pada Back Office Merchant bersifat *read-only* bagi Merchant Owner.<br>2. Penyesuaian nilai parameter bisnis dan tarif MDR khusus hanya dapat dikonfigurasi melalui portal Back Office Bank oleh User Bank. |
| Keterbatasan | 1. Merchant Owner hanya dapat melihat data parameter bisnis dan skema MDR yang terikat pada `merchant_id` milik sendiri.<br>2. Merchant Owner tidak memiliki akses untuk mengubah nilai parameter bisnis atau tarif MDR dari halaman ini. |
| Aturan Bisnis/Sistem | 1. **Merchant Scope Filtering Constraint:** Data parameter bisnis dan skema MDR yang disajikan WAJIB difilter secara eksplisit hanya untuk `merchant_id` dari sesi Merchant Owner yang sedang login.<br>2. **MDR Rate Determination Logic:** Tampilan tarif MDR pada tab MDR WAJIB menampilkan tarif khusus dari `mst_merchant_mdr_details` jika berstatus aktif (`is_override = true`), atau menggunakan tarif default dari `business_type_category_details` jika tidak ada *override*.<br>3. **Read-only Presentation Standard:** Seluruh elemen informasi pada tab Business Rules dan tab MDR disajikan secara *read-only* tanpa kontrol pengeditan.<br>4. **Audit Trail Standard:** Setiap aktivitas pengaksesan halaman parameter bisnis dan MDR merchant mencatat `merchant_id`, `accessed_by` (ID Merchant Owner), dan timestamp pada `audit_logs`. |
| Session Idle | 15 Menit |

# 2 Main Flow

**Tabel 2: Main Flow Menampilkan Parameter Bisnis dan MDR**

| No. | Aktivitas | Deskripsi |
| ---: | --- | --- |
| 1 | Membuka Menu My Business | Merchant Owner melakukan login dan mengklik menu **My Business** pada navigasi Back Office Merchant. |
| 2 | Memilih Tab Business Rules | Merchant Owner mengklik tab **Business Rules** pada halaman My Business. |
| 3 | Menampilkan List Business Rules | Sistem memuat dan menampilkan daftar parameter aturan bisnis merchant (seperti Hari Settlement `H+0`/`H+1`, Minimum Settlement Amount, Frekuensi Settlement) dari `mst_merchant_business_rules` dan `mst_merchants`. |
| 4 | Memilih Tab MDR | Merchant Owner mengklik tab **MDR**. |
| 5 | Menampilkan List MDR Merchant | Sistem memuat dan menampilkan kategori jenis usaha merchant (misal: **UMI** / **UKE**) beserta daftar kriteria nominal transaksi dan tarif persentase MDR yang berlaku dari `business_type_category_details` dan `mst_merchant_mdr_details`. |
| 6 | Meninjau Informasi Parameter & MDR | Merchant Owner meninjau seluruh rincian konfigurasi parameter bisnis dan skema tarif MDR yang diterapkan pada merchant miliknya. |
| 7 | Use Case Selesai | Proses menampilkan parameter bisnis dan MDR merchant selesai dilaksanakan. |

**Tabel 3: Alternative Flow Menampilkan Parameter Bisnis dan MDR**

# 6 Sequence Diagram Menampilkan Parameter Bisnis dan MDR

```plantuml
@startuml
title Sequence Diagram - Menampilkan Parameter Bisnis dan MDR

actor "Merchant Owner" as user
boundary "Front-End" as fe
control "API Gateway" as gateway
control "Merchant Management Service" as service
database "QRIS Database" as db

user -> fe : Akses Menu My Business & Klik Tab "Business Rules"
fe -> gateway : Request Get Merchant Business Rules (merchant_id)
gateway -> service : Teruskan Request Get Business Rules
service -> db : SELECT rule_code, rule_name, rule_value, description FROM mst_merchant_business_rules WHERE merchant_id = ?
service -> db : SELECT settlement_day_type FROM mst_merchants WHERE merchant_id = ?
db --> service : Return Business Rules Data
service --> gateway : Response Business Rules Payload
gateway --> fe : Response Business Rules Payload
fe --> user : Tampilkan List Parameter Business Rules (Hari Settlement H+0/H+1, Min Amount)

user -> fe : Klik Tab "MDR"
fe -> gateway : Request Get Merchant MDR Rules (merchant_id)
gateway -> service : Teruskan Request Get Merchant MDR Rules
service -> db : SELECT m.business_type_id, c.category_name, d.criteria_name, d.min_amount, d.max_amount, d.mdr_rate AS default_rate, o.override_mdr_rate, o.is_override FROM mst_merchants m JOIN business_type_categories c ON m.category_id = c.category_id JOIN business_type_category_details d ON c.category_id = d.category_id LEFT JOIN mst_merchant_mdr_details o ON d.detail_id = o.detail_id AND o.merchant_id = m.merchant_id WHERE m.merchant_id = ?
db --> service : Return MDR Rules Payload
service --> gateway : Response MDR Rules Payload
gateway --> fe : Response MDR Rules Payload

service -> db : INSERT INTO audit_logs
db --> service : Confirm Audit Log

fe --> user : Tampilkan Kategori Jenis Usaha & List Kriteria & Tarif MDR Merchant
@endl
```
