# 1 Deskripsi Use Case

**Tabel 1: Deskripsi Use Case Update Password Expired Merchant Owner**

| Elemen Spesifikasi | Deskripsi Detail |
| --- | --- |
| ID Use Case | UC-BOM-004 |
| Nama Use Case | Update Password Expired Merchant Owner |
| Penjelasan Singkat | Proses pembaruan kata sandi (*force redirect*) yang wajib dilakukan oleh Merchant Owner saat login reguler mendeteksi kata sandi telah kedaluwarsa (`password_expired_at <= CURRENT_TIMESTAMP`), melalui verifikasi OTP email via OTP Service hingga pembuatan password baru sesuai kriteria standar CITRA dengan perlindungan anti-bypass. |
| Aktor Utama | Merchant Owner |
| Aktor Pendukung | OTP Service, Email Service |
| Deskripsi Singkat | Merchant Owner memasukkan email dan password lama pada Halaman Login Back Office Merchant. Auth Service mendeteksi bahwa kata sandi telah kedaluwarsa (`password_expired_at <= CURRENT_TIMESTAMP`), menolak login reguler (*force redirect*), dan memicu OTP Service untuk mengirimkan kode OTP ke email terdaftar. Merchant Owner menginputkan kode OTP, Auth Service memverifikasi OTP dan membuat `otp_verification_token` anti-bypass di Redis Cache, lalu menampilkan form pembuatan password baru. Merchant Owner menginput password baru sesuai kriteria standar CITRA. Auth Service memvalidasi token anti-bypass, kriteria CITRA, serta 10 riwayat password terakhir sebelum menyimpan password baru, memperbarui `password_expired_at = CURRENT_TIMESTAMP + 90 hari`, dan memberikan token sesi. |
| Pre-condition | 1. Akun Merchant Owner telah terdaftar di `mst_users` dengan `login_type = 'REGULER'`, `login_status = 'ACTIVE'`, dan `first_time_login_status = 'COMPLETED'`.<br>2. Kata sandi akun Merchant Owner telah kedaluwarsa (`password_expired_at <= CURRENT_TIMESTAMP` / Hari ke-91). |
| Post-condition | 1. Password lama berhasil diganti dengan password baru yang memenuhi kriteria standar CITRA.<br>2. Tanggal kedaluwarsa kata sandi pada `mst_users` diperbarui menjadi `password_expired_at = CURRENT_TIMESTAMP + 90 hari`.<br>3. Sesi pengguna disimpan pada Redis Cache, dan Front-End mengarahkan Merchant Owner ke Halaman Utama (Dashboard) Back Office Merchant. |
| Trigger | Merchant Owner memasukkan kredensial saat login reguler dan sistem mendeteksi `password_expired_at` telah lewat (`<= CURRENT_TIMESTAMP`). |
| Nama Tabel | mst_users, mst_role_permissions, mst_role_menus, audit_logs |
| Integrasi | 1. **Redis Cache:** Penyimpanan temporary OTP, token anti-bypass (`otp_verification_token`), rate limit counter, dan session token.<br>2. **OTP Service:** Layanan pembuatan, validasi, dan manajemen siklus hidup kode OTP.<br>3. **Email Service:** Layanan pengiriman fisik email kode OTP ke alamat email terdaftar Merchant Owner. |
| Asumsi | 1. Merchant Owner mengingat kredensial email dan password yang kedaluwarsa.<br>2. Merchant Owner memiliki akses aktif ke alamat email terdaftar pada `mst_users`.<br>3. Layanan OTP Service, Email Service, dan Redis Cache beroperasi dengan stabil. |
| Keterbatasan | 1. Pengguna tidak dapat melewati (*bypass*) alur pembaruan kata sandi untuk mengakses Dashboard apabila `password_expired_at` telah kedaluwarsa.<br>2. Pembaruan password baru tidak dapat diproses tanpa memverifikasi kode OTP dan menyertakan `otp_verification_token` anti-bypass yang valid. |
| Aturan Bisnis/Sistem | 1. **Expired Password Detection & Force Redirect:** Pada saat login reguler, apabila `password_expired_at <= CURRENT_TIMESTAMP`, sistem langsung menahan akses (*force redirect*) ke alur Pembaruan Password Kedaluwarsa.<br>2. **Automatic OTP Trigger:** Setelah deteksi password kedaluwarsa, Auth Service otomatis memicu **OTP Service** untuk mengirimkan 6-digit kode OTP dinamis (masa berlaku 5 menit) ke email terdaftar via Email Service.<br>3. **OTP Rate Limit & Attempt Penalty:** Pengiriman OTP dibatasi maksimal 3 kali per menit. Percobaan verifikasi OTP salah maksimal 3 kali berturut-turut sebelum OTP terblokir/hangus.<br>4. **Anti-Bypass OTP Token Mechanism:** Setelah verifikasi OTP berhasil, Auth Service menerbitkan `otp_verification_token` sekali pakai (*single-use*) yang disimpan pada **Redis Cache** (TTL 10 menit). Endpoint pembaruan password WAJIB memverifikasi dan mengonsumsi token ini. Request pembaruan password tanpa `otp_verification_token` yang sah akan ditolak (`403XX00 - Anti-Bypass Violation`).<br>5. **Standar Kriteria Password CITRA:**<br>&nbsp;&nbsp;- Panjang minimal 8 karakter.<br>&nbsp;&nbsp;- Wajib memuat kombinasi minimal 3 dari 4 kriteria: Karakter Spesial (Wajib, mis: `@, #, $`), Huruf Besar (`A-Z`), Huruf Kecil (`a-z`), dan Angka (`0-9`).<br>&nbsp;&nbsp;- Dilarang mengandung User ID, Nama Depan, atau Nama Belakang.<br>&nbsp;&nbsp;- Riwayat Password: Password baru tidak boleh sama dengan 10 riwayat password terakhir.<br>6. **Password Expiry Renewal:** Setelah pembaruan password sukses, sistem mengisi `password_expired_at = CURRENT_TIMESTAMP + 90 hari`, memuat `mst_role_permissions` & `mst_role_menus`, serta membuat sesi di Redis Cache. |
| Session Idle | 15 Menit |
| Expired Sesi OTP | 5 Menit |

# 2 Main Flow

**Tabel 2: Main Flow Update Password Expired Merchant Owner**

| No. | Aktivitas | Deskripsi |
| ---: | --- | --- |
| 1 | Membuka Halaman Login | Merchant Owner membuka halaman login Back Office Merchant pada peramban web. |
| 2 | Memasukkan Kredensial Reguler | Merchant Owner menginput email dan password yang telah kedaluwarsa. |
| 3 | Mengirim Permintaan Login | Merchant Owner menekan tombol "Login", Front-End mengirim request autentikasi ke Auth Service via API Gateway. |
| 4 | Memvalidasi Expired Password | Auth Service memverifikasi kredensial email & password pada `mst_users` dan menemukan `password_expired_at <= CURRENT_TIMESTAMP`. |
| 5 | Pengiriman OTP & Force Redirect | Auth Service menolak login reguler, memicu OTP Service untuk membuat & mengirimkan kode OTP 6-digit ke email Merchant Owner via Email Service, dan Front-End menampilkan modal/form masukan OTP. |

| 7 | Verifikasi OTP & Generasi Token Anti-Bypass | Auth Service memvalidasi kode OTP melalui OTP Service. Setelah cocok, Auth Service membuat `otp_verification_token` dinamis di Redis Cache (TTL 10m) dan mengembalikannya ke Front-End. |
| 8 | Memasukkan Password Baru | Front-End menampilkan form pembuatan password baru. Merchant Owner menginput password baru dan konfirmasi password sesuai kriteria standar CITRA. |
| 9 | Memvalidasi Password & Token Anti-Bypass | Front-End mengirimkan password baru beserta `otp_verification_token`. Auth Service memverifikasi keabsahan token anti-bypass di Redis Cache (lalu mengonsumsi/menghapusnya), serta menguji kriteria password CITRA dan riwayat 10 password terakhir. |
| 10 | Memperbarui Expiry & Sesi | Auth Service memperbarui `mst_users` (`password_hash = hash_baru`, `password_expired_at = CURRENT_TIMESTAMP + 90 hari`), memuat `mst_role_permissions` & `mst_role_menus`, membuat token sesi (JWT) di Redis Cache, serta mencatat `audit_logs`. |
| 11 | Use Case Selesai | Front-End menyimpan token sesi dan mengarahkan Merchant Owner ke Halaman Utama (Dashboard) Back Office Merchant. |

title Sequence Diagram - Update Password Expired Merchant Owner

alt Kredensial Valid DAN password_expired_at <= CURRENT_TIMESTAMP [Force Redirect]
  service -> redis : SETEX otp:{email} 300 {otp_code}
  redis --> service : OK
  service -> otp_svc : Request Generate & Send OTP (email, otp_code)
  otp_svc -> email : Trigger Delivery OTP Email (email, otp_code)
  email --> otp_svc : OK
  otp_svc --> service : Return OK
  
  service --> gateway : 403XX04 (Password Expired - OTP Required)
  gateway --> fe : 403XX04 (Password Expired - OTP Required)
  fe --> user : Tampilkan Modal Input OTP (Peringatan Password Expired H-91)
  
  user -> fe : Input 6-Digit OTP & Klik "Verifikasi OTP"
  fe -> gateway : POST /api/v1/auth/password-expired/verify-otp (email, otpCode)
  gateway -> service : Teruskan verifikasi OTP
  
  service -> otp_svc : Validate OTP (email, otpCode)
  otp_svc -> redis : GET otp:{email}
  redis --> otp_svc : Return otp_code
  otp_svc --> service : Return Validation Result
  
  alt Kode OTP Salah / Expired [AF-01]
    service --> gateway : 400XX00 (Kode OTP Invalid)
    gateway --> fe : 400XX00 (Kode OTP Invalid)
    fe --> user : Tampilkan "Kode OTP salah atau telah kedaluwarsa"
  else Kode OTP Valid
    service -> redis : DEL otp:{email}
    service -> redis : SETEX anti_bypass_expired:{email} 600 {otp_verification_token}
    redis --> service : OK
    service --> gateway : 200XX01 (OTP Verified + Return otp_verification_token)
    gateway --> fe : 200XX01 (OTP Verified + Return otp_verification_token)
    fe --> user : Tampilkan Form Pembaruan Password Baru
    
    user -> fe : Input Password Baru & Klik "Simpan Password"
    fe -> gateway : PUT /api/v1/auth/password-expired/change-password (email, newPassword, otp_verification_token)
    gateway -> service : Teruskan permintaan ubah password
    
    service -> redis : GET anti_bypass_expired:{email}
    redis --> service : Return stored_token
    
    alt Token Anti-Bypass Kosong / Tidak Cocok / Expired [AF-03]
      service --> gateway : 403XX00 (Anti-Bypass Violation)
      gateway --> fe : 403XX00 (Anti-Bypass Violation)
      fe --> user : Tampilkan "Akses ditolak. Verifikasi OTP wajib dilakukan terlebih dahulu"
    else Token Anti-Bypass Valid
      service -> service : Validasi Kriteria Password CITRA & Check 10 Password History
      alt Password Tidak Memenuhi Kriteria / Terdaftar di History [AF-04 / AF-05]
        service --> gateway : 422XX00 (Kriteria Password Invalid)
        gateway --> fe : 422XX00 (Kriteria Password Invalid)
        fe --> user : Tampilkan "Password baru tidak sesuai kriteria CITRA atau riwayat 10 password"
      else Password Baru Valid
        service -> redis : DEL anti_bypass_expired:{email}
        service -> db : UPDATE mst_users SET password_hash = ?, password_expired_at = CURRENT_TIMESTAMP + INTERVAL 90 DAY WHERE email = ?
        db --> service : OK
        service -> db : SELECT * FROM mst_role_permissions & mst_role_menus WHERE role_id = ?

        service -> redis : SETEX session:{token} 900 {session_data_access_token_15m}
        redis --> service : OK

        db --> service : OK
        service --> gateway : 200XX02 (Password Expired Update Success + Access Token 15m)
        gateway --> fe : 200XX02 (Password Expired Update Success + Access Token 15m)

      end
    end
  end
